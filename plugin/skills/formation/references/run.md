# Run and resize a formation

- Add a unit by running startup for that workspace, updating the roster and telling the aide. To resize, quote the operator’s direction on the existing captain’s record. Keep that captain and assignment. Brief only the added seats and wind down the removed ones. Record the new attention owner.
- Routine clearing goes to the sergeant. Order the lieutenant for heavy triage, root cause, implementation, PR rescue and review. Give one task, result and deadline at a time. Keep one writer per file set and record context files. Use persistent worktrees. A scratchpad holds disposable cursors, logs and inputs. In Constellation use the umbrella’s worktrees directory and its ignored tmp directory for host scratch.
- Keep an Orbit-published candidate on its accepted head. Record a red check on its task so the delivery run repairs it. In a squad, claim mechanical base-CI fixes immediately and send the PR to the captain. A failure needing diagnosis or a change to an assertion or guard goes to the lieutenant. A lieutenant never reviews its own work.
- Ask for one reinforcement by rank and reason. The chief can authorize up to a squad plus one extra lieutenant per workspace under the standing staffing mandate. Beyond that, ask the operator. Record the new seat, routes, model and reader. Apply the provider’s actual capacity and launch constraints.
- Short fan-out is a bounded subagent assignment where authorized. Only the operator adds a standing specialist. It earns a seat when multiple units repeatedly need the same subject. The chief and captains may ask it, and a lieutenant only when given its ID for an order. Send one question, source record, needed answer and fallback at next wake. The specialist replies to that asker with evidence. It may record a lasting answer on the named task.
- The room’s shared reader (`formation watch run`) runs all `on` watches and mails findings on change; any joined seat can manage ad hoc watches while it runs (changes apply on the next pass, within 10s, without restart).
- Test a probe without altering the room with `formation watch check -- <command>`. Add or replace a watch with `formation watch add <name> [--to <seat>] [--every <seconds>] -- <command>` (default 120s, min 10s; `--to` defaults to caller; replaces matching `(to, name)` keeping remembered fingerprints).
- Inspect reader, standby and per-watch state with `formation watch list [--json]`. Pause or resume with `formation watch pause|resume <name> [--to <seat>]`, and drop with `formation watch remove <name> [--to <seat>]` (forgets fingerprints).
- For sentry `rest` and `watch` orders, pause or resume the unit’s watches (`formation watch pause|resume ...`) rather than killing the shared reader; without a sentry, the captain or sergeant pauses/resumes them directly. The sentry still handles `mute` lines and the hourly digest (`assets/brief-sentry.md`). When transferring attention to a resident, pause or remove the unit’s `attention` watch. A chief who learns the operator started a drain alerts the responsible captain immediately.
- A reader renews its lease every 15s and a standby takes over after 45s. Probes run in the active reader’s environment and saved `cwd`; failures show `read failed` in `watch list` and mail once until a clean read recovers.
- If all readers stop without `formation watch stop`, affected seats receive one `watch: nothing has read...` notice at their next hook event; run `formation watch list` and start `formation watch run` in a live seat’s background shell. Keep the chief’s fallback probes conditional until the seat-network design settles their recipient.
- A solo captain with open work can sit idle. In a duo, a review may wait for the hourly digest. If the host provides an authorized check, inspect outstanding records and request a status once from an idle owner. Avoid duplicate watches. Outcome, evidence and ask belong in the opening 400 characters of a report.
